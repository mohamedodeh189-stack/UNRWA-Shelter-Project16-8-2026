# Beneficiary Package Export — تصدير ملف المستفيد النهائي

> **الحالة: مواصفة رسمية معتمدة للتصميم — لم تُبرمَج بعد.** أُضيفت 2026-08-08 بناءً على طلب المستخدم، مرجعُها بنية مجلد مستفيد حقيقي (عبد القادر محمد السكري) وملف DXF حقيقي. هذه الوثيقة تُقرّ *ماذا* نبني قبل كتابة أي كود. لا تنفيذ قبل اعتماد لاحق.

## 1) الهدف
بعد اكتمال دراسة/متابعة المستفيد، يضغط المهندس **زراً واحداً** فيجهّز التطبيق **مجلد تسليم كامل** جاهزاً للنسخ مباشرة إلى اللابتوب أو التسليم. المجلد يحمل اسم المستفيد ويحتوي كل مخرجاته (تقييم + مخطط CAD + صور المراحل + نسخة بيانات).

## 2) مبدأ حاكم: DXF هو الأصل الهندسي، PDF نسخة عرض فقط
- التطبيق يصدّر **DXF** كملف CAD أساسي — يفتحه المهندس في AutoCAD ويعدّله.
- يصدّر **PDF** كنسخة عرض فقط (لا يُعتبر الأصل). إن احتاج المهندس PDF محدّثاً بعد التعديل، يحفظه من AutoCAD.
- كل مخطط يبقى **مرتبطاً بمستفيده** (ملف `house_<id>.json` لكل مستفيد) — مخطط أحمد لا يختلط مع محمد.

## 3) بنية المجلد — مستفيد واحد
عند الضغط على **«تصدير ملف المستفيد»** داخل ملف المستفيد:
```
<اسم المستفيد>/
├── 01_التقييم_والكميات/
│      └── <اسم المستفيد>.xlsx        ← التقييم/الكميات (BOQ)
├── 02_المخطط/
│      ├── <اسم المستفيد>.dxf         ← الأصل الهندسي (DxfWriter)
│      └── <اسم المستفيد>.pdf         ← نسخة عرض (PdfExporter)
├── 03_صور_قبل_الترميم/              ← من مرحلة الدراسة (BEFORE)
├── 04_صور_أثناء_الترميم/            ← من مرحلة المتابعة (DURING)
├── 05_صور_بعد_الترميم/              ← من مرحلة المتابعة (AFTER)
└── 06_نسخة_البيانات/
       └── backup.json               ← نسخة بيانات المستفيد (استعادة/أرشفة)
```
**قواعد:** اسم المجلد الرئيسي = **`اسم المستفيد - رقم التسجيل`** (رقم التسجيل يُلحق إن وُجد لمنع التكرار؛ إن لم يوجد رقم تسجيل يُستخدم الاسم وحده ثم يُحسم التكرار بلاحقة رقمية — انظر §6). الصور «قبل» من الدراسة؛ «أثناء/بعد» من المتابعة. الناتج جاهز للنسخ فوراً.

## 4) بنية المجموعة — تصدير عدة مستفيدين (بدل «دفعة 50»)
**تُلغى فكرة الحد الثابت 50 نهائياً.** العدد اختيار المستخدم: 1، 20، 50، 100، أو أكثر — بلا حدّ أقصى.
زر جديد **«تصدير مجموعة مستفيدين»** يفتح قائمة اختيار متعدّد:
```
☑ أحمد محمد الشيخ
☑ محمد علي
☑ سعاد أحمد
…
```
ثم ينشئ (اسم المجلد الأب = تاريخ ووقت كاملان لمنع أي خلط):
```
UNRWA_Shelter_Export_YYYY-MM-DD_HHMM/
├── أحمد محمد الشيخ - 12345/     ← نفس قالب المستفيد الواحد (01..06)
├── محمد علي - 12346/
├── سعاد أحمد - 12347/
└── …
```
كل مستفيد في مجلده المستقل بنفس القالب. مستفيد بلا مخطط مرسوم: يُنشأ `02_المخطط` مع ملاحظة «لا يوجد مخطط» (لا DXF/PDF)، وبقية المجلدات كالمعتاد.

## 5) خريطة المصدر — Screen → Existing Function → Data Source
| مجلد الحزمة | المصدر في التطبيق الحالي |
|---|---|
| `01_التقييم_والكميات/*.xlsx` | كميات/تقييم المستفيد في `AppDatabase.Beneficiary` + `QuantityCatalog` (حالياً يوجد **استيراد** xlsx عبر `SpreadsheetImporter`؛ **التصدير كـ xlsx غير موجود بعد** — قرار مفتوح رقم 1). |
| `02_المخطط/*.dxf` | `DxfWriter.toDxf(model)` من `files/drawings/house_<id>.json`. |
| `02_المخطط/*.pdf` | `PdfExporter.export(...)` من نفس النموذج. |
| `03_صور_قبل_الترميم` | `BeneficiaryPhotoManager` طور `BEFORE` (SAF tree، مجلد «01 - قبل الترميم»). |
| `04_صور_أثناء_الترميم` | `BeneficiaryPhotoManager` طور `DURING`. |
| `05_صور_بعد_الترميم` | `BeneficiaryPhotoManager` طور `AFTER`. |
| `06_نسخة_البيانات/backup.json` | بيانات المستفيد — يُعاد استخدام تسلسل `SyncPackageJson`/`StudyRevisionPackage` لكن **لمستفيد واحد** كنسخة استعادة (وليس حزمة تزامن Windows). |

## 6) الوجهة والكتابة (قيود المنصّة)
- التطبيق يكتب عبر **SAF** (المستخدم يختار مجلد الوجهة على الجهاز/بطاقة SD)، تماماً كما يفعل `BeneficiaryPhotoManager` الآن. لا يملك التطبيق صلاحية كتابة عشوائية على نظام الملفات ولا صلاحية إنترنت.
- المجلد الناتج على وحدة تخزين يصلها المستخدم بكابل USB أو مدير ملفات → **جاهز للنسخ إلى اللابتوب**.
- تنظيف الأسماء: اسم المستفيد العربي → اسم مجلد آمن (إزالة المحارف الممنوعة `\ / : * ? " < > |`، قصّ الفراغات).
- **اسم مجلد المستفيد = `اسم المستفيد - رقم التسجيل`** إن وُجد رقم التسجيل. إن لم يوجد، يُستخدم الاسم وحده.
- **حسم التكرار (لا كتابة فوق شيء أبداً):** إن وُجد مجلد بنفس الاسم (سواء مجلد الأب للمجموعة أو مجلد مستفيد داخلها)، تُضاف لاحقة رقمية `_2` ثم `_3` … حتى يصبح الاسم فريداً. **كل تصدير ينشئ نسخة جديدة؛ لا يُمسّ أي مجلد قديم.**

## 7) قرارات محسومة (مُعتمدة 2026-08-08)
1. **ملف 01 (التقييم والكميات):** المواصفة النهائية **xlsx**. يجوز في أول نسخة **CSV مؤقتاً فقط** إن كان توليد xlsx صعباً، لكن الهدف النهائي xlsx (كاتب xlsx بسيط بلا مكتبات خارجية).
2. **مصدر DXF/PDF:** يُولّدان لحظة التصدير من النموذج المحفوظ (الأدق والأحدث).
3. **اسم مجلد المجموعة:** **`UNRWA_Shelter_Export_YYYY-MM-DD_HHMM`** — تاريخ ووقت كاملان (لا السنة وحدها) لمنع الخلط.
4. **إعادة التصدير:** **لا كتابة فوق أي مجلد قديم أبداً.** كل تصدير نسخة جديدة؛ عند تطابق الاسم تُضاف لاحقة `_2`, `_3`, …
5. **اسم مجلد المستفيد:** **`اسم المستفيد - رقم التسجيل`** (رقم التسجيل يُلحق إن وُجد لمنع التكرار)؛ وإلا الاسم وحده ثم لاحقة رقمية عند التطابق.
6. **علاقتها بتزامن Windows الحالي:** حزمة **تسليم بشري (مجلدات + ملفات)** منفصلة عن `SyncTarget` (تزامن بيانات JSON) — لا تُلغي إحداهما الأخرى.
7. **الصور من SAF:** نسخ محتوى ثنائي من شجرة SAF للصور إلى شجرة الوجهة، مع مراعاة الأحجام الكبيرة (شريط تقدّم/إلغاء).

## 8) خطة مرحلية مقترحة (بمحطات، لا تنفيذ الآن)
- **P1 — تصدير مستفيد واحد:** زر في ملف المستفيد ينشئ القالب (01..06)، يولّد DXF+PDF+backup.json، وينسخ صور المراحل. محطة توقف.
- **P2 — تصدير مجموعة:** شاشة اختيار متعدّد (بلا حدّ)، مجلد أب `UNRWA_Shelter_Export_<...>`، تكرار P1 لكل مستفيد مع شريط تقدّم وتقرير نجاح/تخطّي. محطة توقف.
- **P3 — تلميع:** ملف `فهرس.txt`/README داخل كل حزمة، معالجة الأخطاء (لا صور/لا مخطط)، وتقرير ملخّص التسليم.

## 9) خارج النطاق / غير مطلوب الآن
- لا رفع سحابي ولا شبكة (التطبيق بلا صلاحية إنترنت).
- لا تغيير في قاعدة البيانات ولا في منطق الحالات/الاعتماد/الدفعات المالية.
- لا يُلغى تزامن Windows الحالي.
- **لا برمجة قبل اعتماد لاحق** — هذه مواصفة فقط.
